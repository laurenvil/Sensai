# 🤝 Open Classroom Community Guidelines
Welcome to our collaborative workspace! In this classroom, we are all teachers and we are all students. To ensure a productive and inclusive environment, please follow these core principles.
## 1. The "Code of Review" 🔍Peer review is not about finding bugs; it’s about sharing perspectives. - **Be Kind:** Address the code, not the person. Use "the code could..." instead of "you should..."- **Be Specific:** Don't just say "this is good." Explain *why* it works or suggest a specific improvement.- **The 2-for-1 Rule:** For every Pull Request you open, you are expected to provide meaningful feedback on **two** other peers' PRs.
## 2. Shared Growth (Explorer & Expert Paths) 🚀- **Path B (Explorers):** If you hit a wall, open a "Discussion" or an "Issue." Don't struggle in silence—your question likely helps others.- **Path C (Experts):** Your goal is to improve the curriculum. When you submit a PR to the master repo, include documentation so others can learn from your changes.
## 3. Communication Norms 💬- **Issues as Conversations:** Treat "Learning Contracts" as living documents. If your goals change mid-module, update your issue and tag the teacher.- **Constructive Conflict:** If you disagree with a peer’s approach, offer an alternative solution or a resource (video/article) that explains your reasoning.
## 4. Plagiarism vs. Collaboration 📚- **Collaboration:** Discussing logic, sharing resources, and helping a peer debug their code is highly encouraged.- **Plagiarism:** Directly copying code without understanding or attribution is not allowed. If you use a snippet from a peer or a website, add a comment in your code citing the source.
---*By participating in this repository, you agree to uphold these standards. Let's build something great together!*
